# 小杰AI选股系统 · P2–P5 全策略清点与统计口径审计

**版本**：上线前最终版（2026-10-18）
**范围**：`core/strategies/` 全部战法 + `signal_log` / `signal_pnl` / `strategy_effectiveness` / 模拟盘
**性质**：只审计、只报告。本轮**不改任何策略代码、不改任何阈值、不删任何战法**。
**数据边界**：生产库 `data/quant_data.duckdb` 截至 2026-10-18 17:59；样本仅 5 个交易日。

## 0. 一句话结论

系统「能选股」没问题；「选得准不准」目前**没有任何统计证据**。

- 103 条信号、5 个交易日、P2/P4 零样本、T+10 零样本；
- 所有战法的 Wilson 95% 置信区间都覆盖 50% —— **没有一条战法能被证明优于抛硬币**；
- 面板上的高胜率来自 1~6 个样本，属于噪声，不是结论；
- 上线后的正确姿势：**全部战法按默认权重跑，只用模拟盘攒 100 个交易日，不人工调权、不删战法、不加战法**。

## 4. 统计口径审计（10 项）

### 4.1 收益口径与实盘不一致

- 统计：`(T+N 收盘价 − push_price) / push_price`，持有到 T+N 收盘。
- 实盘模拟盘：**−3% 止损 / +15% 止盈 / T+1 可卖**，到点即卖。
  - ⚠️ **【2026-11-04 历史注记】** 上面这行写的是**审计当日（2026-10-18）**的模拟盘口径。
    - 止盈已由 **+15% → +8%**（V30.11 起统一为 +8%/-3%，所有板一致）
    - 另新增滑点 **0.1%** 与最长持有 **10 个交易日**到期强平
    - 因此本节「两者不是同一个策略」的结论**至今依然成立**，且差距比审计时更大
  - 本文档为**带日期的历史审计报告**，正文保留原貌不改写，仅加此注记；
    现行口径见 `docs/PAPER_TRADING_DESIGN.md` 与 `config.yaml → paper_trading`。
- 两者不是同一个策略，**不能互相印证**。统计里的「胜率」不等于模拟盘会出现的胜率。

### 4.2 未计交易费用

毛收益未扣：佣金万 3（最低 5 元）、印花税万 5（卖出）、过户费十万分之一（双边）。
按单票 20 万、双边约 0.11% 估算，短线 5 日持有会把 1~2 个百分点的优势直接抹平。

### 4.3 样本期极短且单边下跌

5 个交易日，样本期内指数大幅下跌（代码注释记录等权指数约 −29.6%）。
绝对收益为负、超额为正属正常现象，**不能外推**到正常市场。

### 4.4 战法 ID 高度重叠

`P5-05A/B/C`、`P5-02A/B/C`、`P5-03A/B/C`、`P5-13A/B/C` 都是同一段逻辑的分档输出，同一只票会同时命中多个 ID。
**样本不独立**，不能把 A/B/C 当三条独立战法做比较。

### 4.5 时间窗口重叠

T+1 / T+2 / T+5 的样本是同一批信号在不同持有期的结果，**不是三次独立检验**。
把三个档位一起看会虚增「证据量」。

### 4.6 多重检验

50 个 `(pool, strategy, N)` 组合，α=0.05 下期望约 **2.5 个假阳性**。
即使看到一两个「胜率 60%」，也不足以排除偶然。

### 4.7 价格回填：63/103 行走的是收盘价

| 池 | `push_price:<pool>`（信号现价） | `backfill:close`（收盘回填） |
|---|---:|---:|
| P3 | 6 | **5** |
| P5 | 34 | **58** |

- P5 是盘后池，收盘价 ≈ 信号价，**语义可接受**。
- P3 是盘中池，用收盘价回填等于**用未来价格当买入价**，这 5 行必须排除出 P3 统计。
- 新写入已改为记录信号现价（10-13 起全部是 `push_price:p3`）。

### 4.8 P3 时间戳污染

11 条 P3 信号里 5 条在 01:52 / 07:53 写入，属手工或回放；真实盘中只有 6 条。
根因与处置见 `docs/SIGNAL_LOG_TEST_POLLUTION.md`（已有 `XJ_NO_SIGNAL_PERSIST` 旁路）。

### 4.9 数据质量标记从未真正触发

`signal_log` 的脏样本标记只有 `LIMIT_RULE_*` 一类；`NEW_STOCK_SUBSET`、`SUSPENDED`、`ADJ_*` **一次都没出现过**。
说明「排除新股 / 停牌 / 复权异常」的过滤器**从未被样本验证过**，不能假设它有效。

### 4.10 【重要】胜率面板存在跨档重复计数

- 位置：`core/strategy_weight_optimizer.py:139-152` 按 `(pool, strategy, stat_n_days)` 去重，T+2 与 T+5 **两行都保留**；
- `:206-212` 把两档的 `n_signals` 直接相加、`:258` 用 `weighted_sum / total_n` 算总胜率；
- 结果：`P5-02B` 面板显示 **83.9%**，实际是 `(9×75% + 5×100%) / 14`，而它真正的 T+5 行是 **9 条信号 / 2 条已评估 / 50.0%**；
- `n_evaluated` 同样被重复计数（4+2=6）。

**影响**：`data/strategy_weight_recommendation.json` 给 `P5-02B` 打了 `1.2 · 高胜率`。因为 `auto_apply=False`，**不会真的改权重**，但会误导人工判断。

**已修复（2026-10-18）**：`core/strategy_weight_optimizer.py:154-186`
- ① 先按战法定出唯一采用档位 `own_primary = max(available_n_days ∪ {stat_n_days})`；
- ② 聚合时只接受 `stat_n_days == own_primary` 的行，跨池只合并同一 N 档。
- 同步更新 `core/FIELD_CONTRACT.md` 的口径说明。
- 修复后 P5-02B 从「83.9% / n_signals=14 / n_evaluated=6」变为「**50.0% / n_signals=9 / n_evaluated=2**」，与库中真实 T+5 行一致。
- 影响面：仅报表与 UI 面板展示数字，**不改评分权重、不改策略逻辑、不改任何阈值**。
- 回归：`verify_system.py` 80/0/0；回归 1~4+6 共 178/123/24/93/34 全绿；模拟盘 16/16；防污染 58/58；无副作用 127/0；`compileall` exit=0。
