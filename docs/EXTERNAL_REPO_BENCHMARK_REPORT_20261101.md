## 零、先说结论

### 0.1 一句话总结

**你的系统在这个赛道里已经是「工程纪律顶级、策略验证不足」的那一类。**

12 个对标项目里，没有一个在「理由可追溯 / 数据质量标记 / 死条件审计 / 心跳可观测 / 单写者约束」这些维度上做得比你深。
但它们在**另外三个方向**上集体领先你：

| 领先方向 | 代表项目 | 你缺什么 |
|---|---|---|
| **① 策略验证的统计严谨性** | tick-stock-panel、hikyuu、Vibe-Research、day-trader-skill、augur | 你只有「样本内命中数 / 最高分」曲线，**没有样本外折外检验、没有成本约束、没有前瞻收益曲线**。这是当前最大的能力缺口。 |
| **② 组合 / 持仓 / 事件 / 告警层** | Vibe-Research、PanWatch、OpenStock、day-trader-skill | 你的系统**只产出「候选清单」，不管理「仓位与已持仓」**。模拟盘是自闭环实验，不等于真实持仓台账。也**没有任何告警、事件日历、复盘**。 |
| **③ 对外可编程接口** | aktools、tick-stock-panel、Vibe-Research、augur、PanWatch | 你**没有 MCP / HTTP API / CLI 契约**。系统只能通过 Streamlit 点、企微推，人是唯一的消费者。AI 助手无法安全地读你的数据。 |

### 0.2 三个「立刻就能吃掉」的洞

我在代码里实测到三个**模块已经写好但没接线**的空洞——这是最高 ROI，因为代码已经在那了：

| # | 发现 | 证据 | 影响 |
|---|---|---|---|
| **H1** | `core/market_sentiment.py` 的 **8 状态 × 5 池情绪系数表（`SENTIMENT_POOL_MULTIPLIER`）是死代码**。全仓唯一调用点是 `core/notification/deepseek.py:1148`（只拿去给 AI 提示词做上下文）；`strat_base.py:512` 用的是自己硬编码的 `冰点→0.94 / 高潮→0.98` 两档；`ui/app.py:1716` 写的 `market_sentiment` 是 regime 的二级词，不是 8 状态 | `rg "SENTIMENT_POOL_MULTIPLIER"` 全仓 0 个消费者 | 你精心设计的「退潮期 P2/P3 门槛打 0.6 折」**从来没生效过**。这是 31 条战法的真实行为偏差。 |

### 0.3 一句话建议

> **不要加战法，先加「证伪机制」。**
>
> 你现在有 31 条战法、216 个文件、9.6 万行代码，但 `strategy_effectiveness` 只有 69 行、
> `signal_log` 只有 120 条 / 7 个交易日，距离「哪条战法真的有用」还差 **2~3 个月样本积累**。

> 正确顺序是：先把 **样本外折外检验 + 成本约束 + 前瞻收益曲线** 建起来（学 TSP / Vibe-Research），

## 二、逐仓库深度分析与可借鉴点

### 2.1 aktools（akfamily）— AKShare 的 HTTP API + MCP 网关

**它是什么**：把 AKShare 的 1000+ 接口用 FastAPI 包成 `GET /api/public/{接口名}?参数`，同时提供 MCP server（`search_interfaces` / `describe_interface` / `get_data` 三个工具），让 Claude / Cursor 用自然语言直接取数。

**特色功能（可借鉴的）**
1. **接口目录可自省**：`/api/interfaces?q=关键词` 搜索 + `/api/interfaces/{名}` 看参数、默认值、说明。**这就是一份机器可读的数据源契约。**
2. **结果缓存 TTL 60s + `X-AKTools-Cache: hit` 响应头**：同参请求 60 秒内不重复打上游，降低被封 IP 风险。
3. **状态码语义化**：401 鉴权 / 400 参数错 / 404 接口不存在 / 429 上游限频 / 502 上游改版。
4. **`_format=csv|xlsx`** 一键下载表格，CSV 带 BOM 直接 Excel 打开。
5. **Token 鉴权 + `--host 0.0.0.0` 局域网共享**。

**对你的价值**

| # | 借鉴点 | 落地方式 | 难度 |
|---|---|---|---|
| **A-1** | **给 `config.yaml` + 字段契约做「接口目录」**。你有 `core/FIELD_CONTRACT.md`，但那是给人看的 Markdown。做成机器可读 JSON（字段名 / 类型 / 单位 / 来源接口 / 是否必填 / 量纲陷阱），然后 `verify_system.py` 按契约校验实际表结构 | 新增 `core/field_contract.json` + `tools/_verify_contract.py` | 低 |
| **A-2** | **数据源插件化 + 能力声明（fail-closed）**。学 TSP 的「能力路由矩阵」：每个数据源声明它能提供什么、单位是 `%` 还是 `0~1`；**声明缺失就拒收，不静默降级**。你已经在 P2 量纲陷阱处做了一次局部处理（`amount` 千元 vs 元不一致时不强行否决），但没有系统化 | `data/sources/{tushare,hithink,akshare}/plugin.yaml`，统一 `fetch(dataset, **params)` 出口 | 中高 |
| **A-3** | **多源兜底 + 缓存 TTL**。你的 Tushare 限速器（400 次/分）是好的，但**没有兜底源**。加 AKShare（免费、无积分）作为 `trade_cal` / `stock_basic` / `daily_basic` 的第二源，HiThink 失败时用 AKShare 顶上，**避免「静默跳过」变成「无数据但看起来正常」** | 见 8 中 G8 | 中 |
| **A-4** | **对外 MCP Server**：把你的「查某只票为什么没进池 / 今日五池结果 / 战法胜率」暴露成 MCP 工具，让 Cursor 直接问。这比让人读 Streamlit 快 10 倍 | `mcp-server/` 目录，3~5 个只读工具 | 中 |

> **注意**：aktools 本身是「AKShare 的网关」，不是选股系统。**你不需要引入 aktools 这个服务**（多一个常驻进程 = 多一个故障点），你真正要抄的是它的**接口契约化 + 缓存 + 状态码**三件套，以及 **AKShare 作为兜底数据源**。

### 2.3 a-share-quant-selector — B1 图形相似度匹配 + K 线推送

**它是什么**：碗口反弹策略 + **B1「完美图形」匹配**（基于 10 个历史成功案例做四维加权相似度排序：双线结构 30% / 量比特征 25% / 价格形态 25%(DTW) / KDJ 状态 20%）。

**特色功能（可借鉴的）**

| # | 它的做法 | 落地方式 | 难度 |
|---|---|---|---|
| **C-1** | **「剔除最大阴量」过滤**：M 天回顾期内成交量最大的一天如果是阴线 → 直接剔除 | **这是极高 ROI 的一个规则**，且你现有字段全够：`df.rolling(M).vol().idxmax()` 那天 `close < open` 就否决。你 55 维里有 `vol` / `open` / `close`。逻辑含义（大资金在最高量那天出货）非常硬 | **低**。建议作为**全局否决**加在 `novice_guard` 之后、策略之前 |
| **C-2** | **DTW 价格形态相似度**做候选排序 | 高级。可以先用更简单的**归一化价格曲线余弦相似度**替代 DTW。但前提是先有「成功案例库」——**而你的 `strategy_effectiveness` 就是天然的案例库**（哪条战法在什么形态下 T+5 赚得多） | 中高（依赖 G1 先修好） |

### 4.1 方案 1 的具体建议（最高 ROI，代码已在）

**现状**：`core/market_sentiment.py` 定义 8 状态 × 5 池的 `SENTIMENT_POOL_MULTIPLIER`，例如：
- `退潮中段` → P2/P3 = **0.60**
- `冰点期` → P2/P3 = **0.50**
- `高潮期` → P2/P3 = **1.20**

**目标**：让它真正影响 `pass_line`（入池门槛）与推送门槛。

**建议的落地形态（分三步，每步可回退）**：

1. **补齐情绪指标输入**。当前 `classify_market_sentiment` 只有 5 个参数。补上 Vibe-Research 的「赚钱效应」（昨日涨停今日平均涨跌）、「炸板率/封板率」、「两市成交额 20 日分位」、「连板梯队分布」。
2. **加 Shadow 模式**（照抄你 V31 B-1 的做法）：新口径只写 `data/runtime/sentiment_shadow.jsonl`（旧判定 vs 新判定 + 差异样本），**不改任何过滤逻辑**。
3. **跑满 2 周后人工对比**，确认差异方向合理，再启用一个池（建议先 P3，样本最多）→ 再推广。

> **这一步的价值**：它把「市场情绪」从**报告型**变成**控制型**，而且**改的是门槛不是权重**，A/B 成本最低。

### 4.2 方案 3+4 的具体建议（回测诚实化）

**当前**：`core/backtest_runner.py` 的 `run_painpoint_backtest` 用 `fwd_arr`（未来收盘价序列）算「平均收益」「近似最大回撤」，**没有任何 A 股交易约束**。

**目标口径**（与 `core/paper_trading/engine.py` 对齐）：

```
信号在 T 日产生（T 日收盘后可知）
  → 最早成交：T+1 开盘价
  → 若 T+1 一字涨停 / 停牌 → 递延到 T+2…（最多 N 日），超过则放弃
  → 卖出：按出场模板的止损/止盈触发，取触发日的价格
  → 费用：佣金 0.03%(最低5元) + 印花税 0.05%(卖出) + 过户费 0.001%(双边)
  → 整手：主板 100 股起；创业板/科创板 200 股起、之后 1 股递增
  → T+1：当日买入不可当日卖出
  → 输出：净收益率、胜率、盈亏比、最大回撤、夏普、卡玛、成本吃掉多少个百分点
```

**关键**：**`core/paper_trading/fees.py` 和 `engine.py` 里这些逻辑已经写好了**（方案 3 只需把它们抽成公共模块），所以方案 3 是「搬代码」，方案 4 才是真正的工程量。

> **预期收益**：你的历史回测数字会**下降**。这不是退步，是从「自我欺骗」回到「真实预期」。
> **但在下降之前，不要用这些数字做任何调参决策。**

### 4.3 方案 5 的具体建议（数据源能力声明）

参考 TSP 的「能力路由矩阵」，做一个最小版本：

```
data/sources/

    plugin.yaml:
      dataset: daily
      capabilities: [adjust=qfq, circ_mv, turnover_rate_f, ...]
      pct_unit: percent        # 必填，未声明 → fail-closed 拒收
      fallback: akshare
  hithink/
    plugin.yaml:
      dataset: limit_up_pool
      capabilities: [seal_amount, first_seal_time, open_count, ...]
      fallback: akshare

```

配合：
- **统一 fetch 出口**：`fetch(dataset, date, **params) -> DataFrame`，每个源实现同一签名

> **这直接解决 G8**：现在「数据没拉到」和「数据正常」在 UI 上长得一样。
